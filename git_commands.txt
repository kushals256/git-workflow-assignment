Commands are listed in the order I ran them.


Step 1: Setting up the local repo

mkdir git-workflow-assignment
    Makes the project folder.

cd git-workflow-assignment
    Goes into the folder so the next commands run there.

git init -b main
    Turns the folder into a Git repo and names the first branch main.

git status
    Shows which files are new, changed or staged, and which branch I'm on.


Step 2: Commits, branching and merging

git add index.html about.html
    Stages both HTML files for the first commit.

git commit -m "Initial commit: add index.html and about.html"
    Saves the starting state of the project.

git diff
    Shows what I changed in index.html before staging it.

git add index.html
    Stages the edited index.html.

git commit -m "Update index.html: add last-updated note"
    Second commit, with the change to index.html.

git branch feature
    Creates a branch called feature at the current commit.

git branch
    Lists the branches. The one I'm on has a * next to it.

git switch feature
    Moves me onto the feature branch. Older guides use git checkout for this.

git add about.html
    Stages the change I made to about.html on the feature branch.

git commit -m "Feature: add team section to about.html"
    Commits that change to feature only. main doesn't have it yet.

git switch main
    Goes back to main.

git merge --no-ff feature -m "Merge branch feature into main"
    Brings the feature work into main. --no-ff makes Git create a merge
    commit, so you can still see the branch in the history.

git log --oneline --graph --all --decorate
    Prints the history as a graph with one line per commit, so the
    branch and the merge are easy to see.


Step 3: .gitignore

The .gitignore file has two rules: *.log (any log file) and temp/
(the whole temp folder).

cat .gitignore
    Prints the file so I can check the rules.

git add .gitignore
    Stages the file.

git commit -m "Add .gitignore to ignore .log files and temp/ folder"
    Commits the rules so they apply for anyone who clones the repo.

git status --ignored
    Lists ignored files too. debug.log and temp/ show up here, which
    means Git won't track them.


Step 4: Undoing a commit

git commit -m "Temporary commit to be undone"
    An extra commit made just so I could undo it.

git log --oneline -3
    Shows the last three commits. I ran it before and after the undo.

git reset --hard HEAD~1
    Moves the branch back one commit and throws away its changes. It
    rewrites history, so I only used it before pushing anything.

git revert --no-edit HEAD
    Undoes the last commit by adding a new commit that reverses it. The
    history stays intact, which is why it's the safer option once
    commits are on GitHub.


Step 5: GitHub

gh repo create git-workflow-assignment --public
    Creates an empty public repo on my GitHub account from the terminal.
    You can do the same thing from the New repository page on the site.

git remote add origin https://github.com/kushals256/git-workflow-assignment.git
    Links my local repo to the GitHub one under the name origin.

git remote -v
    Shows the remote URLs so I could check the link was right.

git push -u origin main
    Uploads main and all its commits. -u means later pushes can just
    be git push.

git push origin feature
    Uploads the feature branch as well.


Later updates

git add README.md git_commands.txt
    Stages the README and changes to this file.

git commit -m "..."
    Commits them with a short message.

git push
    Sends the new commits to GitHub.
